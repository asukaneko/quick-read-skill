# 并行派单手册（多子代理）

本文件是 `SKILL.md` 第 3、5、6、7、8 步的展开。核心一句话：**把「批次 / 单元」当成并行单位，一次派一波子代理，父代理只留调度与校验。**

---

## 1. 哪些环节可以并行

| 环节 | 并行单位 | 每个子代理的输入 | 落盘产出 | 一次并发 |
|---|---|---|---|---|
| 读卡（主力） | 1 个批次 = 12 章 | `计划/批次/批次NNN.md` + 规范 | 12 份 `分章卡片/第NNNN章.md` + 1 份 `单元摘要/单元NN_第A-B章.md` | 3–6 |
| 聚合成账 | 1 本账 | 全部卡片与单元摘要（**不读原文**） | `人物档案.md` / `伏笔与悬念.md` / `故事状态.md` | 3 |
| 撰写速读稿 | 1 个写手 = 2–3 个单元 | 体例说明 + 对应卡片与摘要 | `段/单元NN.md` | 2–4 |
| 补漏返工 | 1 个缺章批次 | 覆盖率报告 + 该批原文 | 补写的卡片 / 速读稿段落 | 1–3 |
| 校验（命令级） | — | — | `check.py` 一步跑完（覆盖率＋切片＋HTML） | 1 |

父代理串行做的事只有：切章建索引、写规范、`make_plan.py` 生成批次、合并速读稿、跑校验、更新 `_进度.md`。

派单前先按 `segment-planning.md` 核对当前段范围。多段项目用 `make_plan.py --segment 第X-Y章`：批次文件在 `计划/批次_第X-Y章/`，清单为 `计划/批次清单_第X-Y章.tsv`，卡片和摘要落在该段目录，编号段内从 01 起。以下派单骨架里的路径相应替换；不传 `--segment` 时沿用单目录的全局编号布局。

```
切章建索引（父）→ make_plan.py 生成批次（父，秒级）
   → 波1..k：读卡（并发 3–6）→ 分章卡片/ + 单元摘要/
   → 波：三本账（并发 3）→ 人物档案 / 伏笔与悬念 / 故事状态
   → 波：速读稿写手（并发 2–4）→ 段/单元NN.md
   → 父：合并 + 双校验 → 缺章按批重派（并发 1–3）
```

---

## 2. 波次调度（怎么派、怎么等）

1. **一波 3–6 个**：这一波没回收完就别加。后台子代理占用本会话模型的故障转移队列并消耗 token，一次开二十个只会互相排队、接连限流失败。
2. **一次性甩出整波**：用后台子代理一次把这一波的几个派出去；每个 prompt 里点名「批次007」，`description` 也带批次号，便于在子代理列表里辨认。
3. **不要空等**：派完立刻去干父代理的活——写下一波的批次文件、写体例、跑已完成批次的校验。子代理结束会自动通知；要查进度用子代理结果查询接口，`status=outputting` 表示工具调用已结束、正在写最终结论，稍等再取，不要反复轮询或 sleep。
4. **回收干净再开下一波**：下一个波次里凡是还没回收的批次，先跳过（同一批被两个代理写会互相覆盖）。
5. **父代理只收一行汇报**：谁回传原文或卡片正文，立即让它停手——那是在把父代理的上下文挤爆。
6. **批次太大就再切**：某批超过 5 万字，先把 `--size` 调小重跑；已经派出去的可以允许该子代理自行委派孙代理对半切（孙代理产出直接落盘，父代理仍只收一行汇报）。
7. **限流或连续失败就先缩并发**：不要原样重试三次，缩到 1–2 个再派；仍不行就父代理亲自读那一批。

## 3. 派单契约（每份 prompt 必须写全这 7 项）

1. 任务一句话（读卡 / 聚合某本账 / 写某几个单元）。
2. 必读文件：规范 `计划/批次规范.md` + 本批批次文件（**绝对路径**）。
3. 输入范围：待读章节的绝对路径清单（批次文件里已列，prompt 里再点一次）。
4. 产出落盘路径：目录 + 命名规则（卡片 `第NNNN章.md` 用 idx 补零；摘要 `单元NN_第A-B章.md`）。
5. 用户偏好：详写什么、压缩什么、切片要多长（不全在规范里就写进 prompt）。
6. 禁止项：不许凭记忆补情节、不许改写切片、不许读别的批次、不许把正文回传。
7. 回报格式：**一行**。

> 子代理没有你的上下文。凡是「它应该知道」的东西，都必须落在文件里。

## 4. 派单提示词骨架（复制即用）

```
你是《{书名}》速读流水线的批次读取代理。

【任务】读完批次文件里列出的全部章节，逐章写卡片，并写 1 份单元摘要。
【必读】{BASE}/计划/批次规范.md（用户偏好与铁律都在里面）
        {BASE}/计划/批次/批次007.md（本批章节的绝对路径清单）
【落盘】卡片 → {BASE}/分章卡片/第NNNN章.md（每章一份，NNNN 用 idx 补零四位）
        摘要 → {BASE}/单元摘要/单元07_第73-84章.md
【纪律】只读上面这些文件；状态优先于事件；原文没写明的标 ⚠️ 原文未明说；
        切片逐字复制（`【原文·第N章 标题】` + `> 「……」`），不许润色拼接。
【回报】只回一行，不要回传原文或卡片正文：
        批次007 完成｜章数 12｜卡片 12｜摘要 单元07_第73-84章.md｜异常：无
```

写手代理、聚合代理用同一骨架，只换【任务】【必读】【落盘】三行：

- 聚合代理：任务＝「只读卡片与摘要，产出 `人物档案.md`」；必读＝全部卡片目录；禁止项加一条「不读原文」。
- 写手代理：任务＝「按体例写单元 5–7」；必读＝体例文件 + 对应卡片与摘要；禁止项加一条「不改章号写法、不改切片格式、不新增小节」。

## 5. 批次规范模板（写一次，全流程复用）

```markdown
# 批次规范（所有子代理必读）

- 书名：{书名}｜工作区：{BASE}
- 用户偏好：详写 ______（升级线/成长线/情感线）；压缩 ______；
  打斗一律写成「为什么打 / 谁打谁 / 胜负与代价 / 对后续的影响」
- 铁律：
  1. 一切以落盘原文为准，不凭记忆补情节；原文没写明标 ⚠️ 原文未明说
  2. 状态优先于事件（谁从什么状态变成什么状态）
  3. 信息差单独记（谁知道了什么、谁还不知道）
  4. 原文切片逐字复制，省略用 ……，不许润色、翻译、拼句
  5. 每章都要有卡片，水章记 C 级但必须写
  6. 不把原文或卡片正文回传父代理
- 卡片格式：见 references/card-template.md（章节标题、一句话、因果链、状态变化、
  新信息、伏笔与悬念、原文切片）
- 分级：S / A / B / C
- 回报：一行
```

生成完立刻替换占位：

```bash
sed -i 's|{BASE}|/workspace/阅读工作区/归墟行|g' 计划/批次规范.md
```

## 6. 回收与重派

| 症状 | 处理 |
|---|---|
| 某批卡片数 < 章数 | 只重派该批，prompt 里点名缺哪几章 |
| 章号写错（把 idx 7 写成第 7 章，但索引里它是第 8 章） | 重派该批，要求「章号一律取批次文件里的 idx」 |
| 覆盖率报告列出缺章 | 把缺章按批次归类，只重派涉及批次补写 |
| `check.py` 切片 FAIL | 按 `校验报告.md` 定位到速读稿段落，逐条回原文修，不要删掉切片了事 |
| 子代理回传了正文 | 记一次违规，下一批把禁止项写得更硬；**不要**把它回传的正文粘进任何文件 |
| 同一批连续失败 2 次 | 缩并发、缩小 `--size`，或父代理亲自读该批 |

重派时复用原批次文件即可，不要为了重派重跑 `make_plan.py`（会覆盖已回收批次的文件名与单元号）。

## 7. 并行撰稿的体例冻结

速读稿最终由父代理合并成一个文件，所以体例必须先冻结，否则合并后两个校验必挂：

1. 父代理先写「体例 + 第 1 个单元样章」，落成 `段/单元01.md`（同时也是给用户的样章），并在规范里声明：标题层级、切片格式、章号写法（`第12章`，不写 `第十二章`）、单元开场句式。
2. 写手代理只按体例写自己那几个单元，**不许自创小节、不许改章号写法、不许把一条切片拆成多行**。
3. 父代理按单元号顺序拼接（`## 单元NN｜小标题（第A–B章）`），只在单元之间补过渡句，不改写手正文。
4. 拼接完立刻跑两个校验脚本——这是把并行产物拉回一个整体的唯一保险。

---

## 8. 成本与边界

- 后台子代理消耗本会话 token、占用故障转移队列，所以「每批只回一行」不是洁癖，是成本控制。
- 别为了「更快」把批次缩到 2–3 章：派单本身有固定开销（读规范、读模板、启动），默认 12 章、长书 8–12 章最划算。
- 不要并行写同一个文件；不要让两个代理处理同一批章；不要把整本原文塞进子代理 prompt。
- 波次规模与书长无关，只与并发上限有关：200 章就是 17 批，照样是 4–6 波跑完。

- [ ] `check.py`：切片全 PASS、0 告警 0 失败
