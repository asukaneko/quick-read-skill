# 分段规划：先定交付范围，再切读卡批次

用户要先规划全书、从断点续规划，或本次范围大到需要分几次交付时，使用本流程。单次范围已经明确时，只需核对入口与末章，再生成段内批次。

## 段、单元与批次

- **段**是一次完整交付：有起读提示、速读稿、资料线、校验结果与下一段断点。目录为 `第X-Y章/`。
- **单元**是段内的连续剧情；**批次**是读卡派单范围。批次默认 12 章，先用于生成摘要；写稿时可以按剧情合并相邻批次，但要保留章号覆盖映射。
- 分段先考虑剧情收束与阅读负担；批次再考虑上下文容量。不要为凑 12 的倍数移动段的剧情断点。

## 1. 确认编号与实际进度

读取 `chapters.tsv`、`_进度.md` 和已有规划；有成品时抽查上一段 `_尾部.md` 与校验报告。

- 所有范围以索引 **idx** 为准；卷内章号重置、重复章、番外等会使 idx 与标题里的章号不同。展示时保留索引原章名，不靠标题里的数字反推 idx。
- 缺失、重复索引或疑似重复原文章节先核对，记录处理口径，不自动把同名章节当作重复删除。
- 续做起点取**已验收成品的实际末章 + 1**。有卡片但未校验交付的范围属于在制任务，先恢复该段。
- 旧规划与实际进度冲突时，保留已完成段，重排后续未执行范围。例如旧规划下一段始于 1967，而已验收成品收至 1985，应从 1986 接读。
- 范围来自用户当前要求；跳章衔接模式只规划跳过区，断点核对也不能读取用户禁止剧透的后续章节。

## 2. 按预算拟范围，再核对剧情断点

没有指定体量时，可先以每段约 80–120 章或约 25–40 万原文字拟草案，按章节平均长度、详写偏好与实际成品体量调整。字数使用索引 `chars` 的同一口径，不能把它自动称为「去空白字数」。

`make_segments.py` 只做索引与预算计算，不判断剧情：

```bash
# 剩余范围按约 100 章拟草案；--dry-run 只预览
python3 tools/make_segments.py --index chapters.tsv --base . --start 121 --end 320 --chapters 100 --dry-run

# 也可按索引字数切草案
python3 tools/make_segments.py --index chapters.tsv --base . --start 121 --end 320 --target-chars 300000

# 核对后指定各段末章；最后一个必须是本次范围末章
python3 tools/make_segments.py --index chapters.tsv --base . --start 121 --end 320 --ends 216,320 --out 计划/分段规划_定稿.md
```

优先使用已确认的卷/篇结构、旧成品和现成卡片判断候选位置；没有这些材料时，定点读取候选末章及相邻章，在允许范围内确认。可以先核对附近 2–3 章，情节仍未收束时再扩展。章名只能帮助找候选，不能作为剧情已核实的证据。

适合断段的位置包括阶段目标达成、战斗与代价交代完整、离开旧场景、进入下一阶段前的状态稳定处。升级、救援、揭密的因果链尚未讲完时，适当延长或缩短本段；连载范围末端尚未收束时，明确标记为范围截断。尾段过短时考虑并入前段，过长时找附近的另一处收束。

分段主题与断点理由必须有原文或已核实卡片依据。只看过索引的远期段保留「暂定／待核对」，执行临近时再细化；不要为填完整规划而通读全书或编造段标题。用户只要规划时，交付规划即可，不自动开始制作全书速读稿。

## 3. 落盘规划并检查连续覆盖

输出 `计划/分段规划_第X-Y章.md` 与同名 TSV。脚本列出段号、idx 起止、章数、索引字数、预计批次、首末章原名、目录与下一段起点；Markdown 留有「断点依据」「状态」两栏，供核对后填写。续规划可以用 `--first-number` 延续段号；旧文件默认不覆盖，`--force` 会重建草案并丢弃手填依据。

在规划中补充用户详略偏好、分段主题、末章为什么适合停，以及核对过哪些 idx；未读后文不要填预计剧情。若主题会剧透，面向读者的段标题改用中性位置名，核对依据留在工作文件。

检查以下关系：

- 第一段起点等于本次起读 idx，最后一段末章等于范围末章。
- 相邻段满足 `后一段.start = 前一段.end + 1`，没有重复或遗漏。
- 每段章数为 `end - start + 1`；段字数求和等于索引范围字数；预计批数为 `ceil(章数 / 批大小)`。
- 断点是末章读完之后；「下一段起读章」与这段的末章不要混写。

生成 TSV 后如调整了边界，应同步更新 Markdown 与 TSV；已有派单的段先回收任务、确认产物归属，再重建受影响的计划。

## 4. 为当前段生成独立批次

先写 `计划/批次规范_第121-216章.md`，包含本段范围、偏好、卡片与正文体例、前段交接状态；然后：

```bash
python3 tools/make_plan.py --index chapters.tsv --base . --start 121 --end 216 --segment 第121-216章 --size 12 --spec 计划/批次规范_第121-216章.md
```

生成：

```text
计划/批次_第121-216章/批次001.md …
计划/批次清单_第121-216章.tsv
第121-216章/分章卡片/
第121-216章/单元摘要/
```

段内批次与单元从 01 编号，输出路径均指向该段；原文仍从书籍工作区 `原文/` 读取。`--spec` 相对书籍工作区解析；原文另存时用 `--src-dir`。`--dry-run` 可先检查范围和文件定位；缺章、重复 idx 会阻止生成，缺原文文件会返回非零退出码，修复后再派单。

不传 `--segment` 保留原有全局网格编号与 `计划/批次清单.tsv` 布局，适用于原有单目录项目。各段独立规划时使用 `--segment`，以免覆盖前段派单。已派出的批次不要为了重试反复生成，直接复用原派单文件。

## 5. 用实际断点回写并滚动修订

完成当前段并通过校验后，更新 `_进度.md`、项目已有的 README 和规划表：实际范围、完成状态、校验结果、下一段起点。若末章从原计划延长或提前，同步修订相邻未执行段，并重新计算章数、字数和批次。

区分规划与进度：规划记录预计边界和核对依据；进度记录实际已验收范围与在制任务。规划完成不等于读卡完成，读卡完成不等于该段交付完成。
