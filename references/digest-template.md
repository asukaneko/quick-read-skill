# 速读稿模板（模式 A）

速读稿是**给用户读的成品**，不是给作者看的分析报告。它要能替代原著：读完知道发生了什么、为什么发生、谁和谁怎么了，重要的地方还能就地看原文。

一句话标准：**用户读完这份稿子再打开原著任意一章，不应该有"这是谁、他为什么在这"的时刻。**

---

## 整体骨架

```markdown

> 按你的偏好整理。最想看：男女主线 / 关键转折｜已压缩：打斗招式、宗门日常。
> 这是删减版，某段没提到不代表原文没写；你随时可以让我把某段展开。
```

## 详略怎么分配

单元里是**一条按章号升序的流**，不再分「重要 / 过渡」两节：读者从本单元第一句顺着读到末一句，章号一路往上，不用回头翻。
每条条目开头就是章号 + 级别标签，级别决定它长什么样：

| 级别 | 标签 | 在这一段里长什么样 |
|---|---|---|
| **S** | `（详）` | 展开写：动机、转折、代价、后果。可以写 2–5 段。配 1–3 条切片。 |
| **A** | `（详）` | 一段到两段，因果完整，不展开描写。 |
| **B** | `（略）` | 一句话到三句，形如「**第 8–11 章（略）**：同门日常与采药，信息量很小，只需知道两件事：… ，这两件分别在第 12、14 章用上。」 |
| **C** | `（略）` | 合并进一句话并标出章号范围：「**第 20–23 章（略）**：赶路与闭关，无实质推进，可以完全跳过。」 |

写法与格式：

- 条目形如 `- **第1285章（详） 金刚诀第四层瓶颈被「打」破**：……`（有标题时）
  或 `- **第1280–1281章（略）**：……`（无标题时）。
- 章号一律用阿拉伯数字、紧跟「章」，范围用 `–`；多章并列可写 `第1340、1341、1342章`。
- **排序只看起始章号**，同一起始章号时「详」在前；同章号多条保持原顺序。
- 章节必须**不重不漏**：本单元所有章都出现在某一条条目里，一条也不许静默丢掉（覆盖率脚本会查）。
- 一条条目可以覆盖多章（`第1286–1287章（略）`），也可以一章拆成两条（`第1290章（详）` 与 `第1290–1291章（详）`），按内容来。

**注意 B/C（略）的写法**：不是"没什么可说的"，而是"压缩到最小但因果仍在"。用户原话是「虽然是不重要的，但还是要讲清来龙去脉」。

## 切片规则

- 只切 S 级，偶尔 A 级。名场面、转折对白、伏笔揭晓那句、人物定调句、结局句。
- 切片**跟着所属章走**：写在该章条目之后（条目与切片之间空一行），不要集中堆在单元末尾；这样顺着读下来，摘要与原文是挨着的。
- 单条 80–500 字。中间可以用 `……` 省略，但**不允许改写、润色、翻译、合并句子**。
- 格式固定（脚本靠它校验和汇总）：

```markdown
【原文·第13章 试炼台上】
> 「他一剑荡开赵乾的兵刃，台下没有一个人出声。」
```

- 全书切片总量建议不超过原文的 15%。超了说明你在替用户"抄书"，不是速读，脚本也会告警。
- 写完跑：

```bash
python3 "$SKILL_DIR/scripts/verify_slices.py" --digest 速读稿.md --source 原文/ --index chapters.tsv --collect 原文切片.md
```

## 交付节奏

- 分单元写入文件，每 1–2 个单元落盘一次，并在对话里给一句进度（「单元二写完，主角已经出书院，接下来进京城篇」）。
- 超过 100 章的书，**先出第 1 个单元当样章**让用户确认详略口味，再全量推进。
- 全部写完后跑 `coverage_check.py`，确认没有静默漏章。
